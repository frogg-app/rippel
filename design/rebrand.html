The generation studio is changing its name from ComfyUI Studio to rippel. This is the identity that comes with it: one mark, four colours, one typeface, and a lockup rule precise enough that nobody has to eyeball it again.

The name

rippel

The working name was Emulsion — a photographic reference, and a reasonable one for a tool that makes images. It described the medium rather than the thing the product actually does, and it had no relationship to the mark that had already been drawn.

rippel is what the logo was already drawing. The mark is a crescent dissolving into rings; the name says the same thing in six letters. It is set lowercase everywhere, including at the start of a sentence — that is a deliberate choice, not a typo to be helpfully corrected in a commit.

The name also happens to be well built for type: the doubled pp in the middle is two identical bowls at the same radius, which is what a ripple is. That symmetry sits at the optical centre of the word.

The mark

A crescent, dissolving

Every stroke is a filled ribbon riding a radius — it swells at mid-span and closes to a point at both ends. There are no strokes anywhere in the artwork and no blunt line endings, so the crescent and the ripples around it are the same primitive at different radii. The mark reads as one system rather than a moon with lines drawn near it.

the mark · 96 / 64 / 44 / 28 / 18 px of ink

Two optical weights

The fine drawing is three rings at 3.8 units of weight. It is designed to fail small — below about 22 px of ink the rings close up and the mark turns to mush. That is solved the way every serious mark solves it: a second cut. The small sibling drops to two rings and roughly doubles the weight, and the renderer switches to it automatically. Never fix small sizes by thickening the display cut.

left: fine cut at 18px — right: the small sibling at the same size
Colour

Rosé Pine, foam to pine

The ramp is taken from the Rosé Pine palette rather than invented, so it has already been argued over by a lot of people. Two steps are the theme's own foam and pine; the two between them are interpolated on the same walk. Colour steps outward from the core: lightest at the centre, deepest on the outermost ring.

mist#c4e2e4core crescent
foam#9ccfd8first ring · UI accent
tide#6a97a8second ring
pine#31748fouter ring

Contrast, honestly. On the product ground #0d1014 the outermost ring measures 3.7:1 — it clears 3:1 for a large graphic, but pine is a ring colour, not a text colour. For type on dark, use foam or lighter.

The ramp does not survive a light ground as drawn. The core is the lightest step, so on #eef3f4 mist falls to 1.2:1 and the crescent at the centre of the mark effectively disappears, while pine sits at a healthy 4.7:1. The mark is built for dark and the app is dark, so this is not blocking — but any light-ground use (invoices, a printed sheet, a light marketing page) needs a darkened variant of the ramp rather than the same four values. It is not drawn yet.

Typeface

Epilogue Light

One face, one weight: Epilogue 300, lowercase, tracked 0.005em. It is a geometric sans with slightly sharper cuts than the neutral options — enough personality to be recognisable next to the mark, not so much that it competes with it. Open licence (OFL), on Google Fonts.

The lockup

Measure ink, never boxes

This is the part that took the longest and the part most likely to be got wrong again, so it is written down as a rule rather than a picture.

The mark's artwork fills only 58×69 of its 120×120 viewBox — 39% of the width on the right is empty, and 29% across the top. A mark placed "at 60px" therefore draws about 34px of visible ink, and a third of any gap you set is invisible padding. Font metrics lie in the same way: declared ascenders do not match rendered ink, and they differ per face.

So both sides are measured as ink. The mark's true bounding box is computed from its own path coordinates after the −34° rotation. The word's ink comes from the browser, for the exact string, at the exact size. Then the two are matched.

Two traps that cost a day

Both produce silently wrong alignment — the page renders, nothing errors, it just sits a few pixels off:

1. Chrome ignores margin-bottom when synthesizing the baseline of a replaced flex item, so nudging an <svg> in an align-items:baseline row does nothing at all. 2. The line-box strut of the container's inherited font pushes an inline-block child down while an absolutely-positioned sibling stays put — invisible at 44px, a full 1–4px at 13px. Place both parts from one known origin instead:

// word ink, from the rasteriser — not from declared metrics
const t = ctx.measureText('rippel');            // ctx.font = "300 ${px}px Epilogue"
const inkH  = t.actualBoundingBoxAscent + t.actualBoundingBoxDescent;
const markH = inkH * 0.85;

// mark ink box, precomputed from the rotated path data
const INK = { x0: 14.70, y0: 35.14, x1: 72.69, y1: 104.06 };
const box = markH * 120 / (INK.y1 - INK.y0);    // the svg element size
const k   = box / 120;

// one origin: the top of the text box, line-height 1
const half = (px - (t.fontBoundingBoxAscent + t.fontBoundingBoxDescent)) / 2;
const inkTop  = half + t.fontBoundingBoxAscent - t.actualBoundingBoxAscent;
const markTop = inkTop + (inkH - markH) / 2;    // centred on the word's ink

svg.style.top  = (markTop - INK.y0 * k) + 'px'; // absolute, never baseline-aligned
svg.style.left = (-INK.x0 * k) + 'px';          // trim the dead padding
lockup.style.paddingLeft = ((INK.x1 - INK.x0) * k + 0.15 * px) + 'px';

Verify it with geometry, not with your eyes: read back getBoundingClientRect() on both ink boxes and assert the centres match. Every lockup on this page is built by the code above and lands within 0.03px of target from 13px to 96px.

In place

Where it lands

The lockup goes in the app header and on the sign-in screen. Everywhere tighter than that — sidebar rail, favicon, tab title, avatar — the mark stands alone. Never re-typeset the word next to the mark by hand; call the lockup component.

How it was arrived at

Nine rounds, then four

Recorded because the rejected directions are the useful part — they are the ones most likely to be proposed again.

1–3Crescents into ripples, 25 marks a sheet. Killed: stroked lines with blunt endings.
4Rebuilt from one primitive — the tapering ribbon. Every terminal closes to a point.
5–7Thinner core, colour carrying the fade instead of opacity. Killed: saturated mint-to-cyan, too far apart in hue and value.
8Twelve palettes, six sourced from real systems — Everforest, Nord, Catppuccin, Rosé Pine, traditional Japanese blue-greens.
9Rosé Pine chosen, on the fine three-ring. Mark settled.
w1Twelve faces plus letterforms drawn from the mark's own primitive. Killed: serifs.
w2Premium light geometrics, monoline drawn cuts. Killed: sizing the mark off font size rather than measured ink.
w3Epilogue Light chosen. Ink-based alignment built, then found broken by screenshot and fixed twice.
w4Mark to 85%, gap to 0.15em. Lockup settled.
Rollout

Renaming the codebase

Verified against the working tree today. The package rename is the one with teeth — the shared package specifier appears in 80 import sites across apps/ and packages/, so it is a single mechanical commit, done in one pass or not at all.

  • apps/web/index.html — <title>Studio</title>→ rippel
  • package.json — "comfy-studio"→ rippel
  • @comfy/web · @comfy/api · @comfy/shared→ @rippel/* · 80 imports
  • README.md · PLAN.md — “ComfyUI Studio”headings + prose
  • favicon + app iconmark alone, small cut
  • POSTGRES_DB=comfy_studio · container comfy-dev-pgleave until a clean env

The database name and dev container are deliberately last: renaming them buys nothing visible and costs a rebuilt volume and a broken HANDOVER.md. Do them when the environment is next rebuilt anyway.

Still open

What is not decided

The 16px cut

The small sibling holds at 18px but is muddy at 13–16px, which is exactly favicon territory. It needs its own drawing — probably one ring and a heavier core — rather than another scale of the same art.

A light-ground ramp

The four values are built for a dark ground and invert badly on a light one — the core reads at 1.2:1. A darkened walk is needed before the mark goes anywhere printed or light.

The two-ring mark

A two-ring variant was drawn and never formally ruled out. It is calmer and survives small sizes better. Worth a decision before the favicon is cut.

Drawn letterforms

A monoline alphabet built from the mark's own ribbon primitive exists for the six letters of the name. It was shelved when Epilogue was chosen. It is the more distinctive answer and the more expensive one — six glyphs is a sketch, not a typeface.
