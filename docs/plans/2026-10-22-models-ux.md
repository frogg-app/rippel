# Models: finding, installing and using them without knowing ComfyUI

Written 2026-10-22, for an overnight run on branch `models-ux`.

## Goals

1. **Installs just work.** No false "wrong folder" verdicts; downloads that
   don't die on a Hugging Face CDN redirect; a model's companion files come
   with it.
2. **Finding a model that works is easy.** Discover opens on *what you want to
   make* and on *what runs on this machine*, with tags as the filter language.
3. **No ComfyUI vocabulary required.** One set of friendly words everywhere,
   with the expert term kept as a quiet secondary label.

## What is wrong today (investigated)

### "Wrong folder"

Not an install error: a verdict computed while the catalogue is listed
(`runnability.ts`), comparing the folder a file *would* land in against the
folder the workflow's loader reads (`FOLDER_READ_BY` in `workflows/folders.ts`)
with a plain string compare. Three separate normalisers decide "the folder"
and disagree:

| Where | Function | `unet` | `clip` | `''` |
|---|---|---|---|---|
| catalogue verdict | `folderForSavePath` (runnability.ts) | → diffusion_models | **clip** | type default |
| install request | `folderForRow` (installs.ts) | **unet** | **clip** | type default |
| agent path | `agentModelPath` (transports/agent.ts) | → diffusion_models | → text_encoders | **null** |

So every legacy ComfyUI-Manager text-encoder row (`save_path: clip`) is
"wrong folder", installs of `unet/…` rows land in a legacy folder that
`/api/models/unet` cannot verify, and an installed file present in two folders
is judged by whichever loader happens to be listed first (`folderOfInstalled`).

Hugging Face entries are all typed `checkpoint` with `savePath: ''`, so FLUX,
Qwen-Image, GGUF repos etc. are judged against `checkpoints/` although they
are diffusion models. (They are install-blocked today, so this mostly shows up
once something else computes their verdict.)

### Downloads failing

`model_operations` failures on the dev install are all
`download host "us.aws.cdn.hf.co" is not an approved model host`: Hugging Face
moved its Xet bridge to `*.cdn.hf.co`, and the agent's allow-list
(`allowedModelURL`, apps/agent/go/models.go) names four exact hosts.

### Vocabulary

`SUPPORT_ROLES` (web models/catalogue.ts) already has plain nouns — Model,
Extra style, Image decoder, Prompt reader, Enlarger, Reference guide — but the
filters, Discover facets, Create page, Settings and progress text still say
Checkpoint, LoRA, VAE, CLIP, "graph", "template", "diffusion_models". `clip`
covers T5 encoders too, so "Technically a CLIP" is wrong for them.

## Plan

### Phase 1 — one folder answer (API + agent)

- `canonicalFolder(savePath, type)` in `workflows/folders.ts`: first path
  segment of either separator, aliases `unet → diffusion_models`,
  `clip → text_encoders`, and the type's folder for `''` / `default`.
  `folderForSavePath`, `folderForRow` and `agentModelPath` all call it; a table
  test asserts they agree.
- `folderOfInstalled` returns every folder that lists the file; "wrong folder"
  only when none of them is the loader's.
- `backendHasFile` checks the canonical folder and falls back to the legacy
  alias.
- Hugging Face entries: infer the folder from the repo/tag facts
  (GGUF / DiT families / `diffusers` single-file transformers →
  `diffusion_models`; VAE → `vae`; LoRA → `loras`) instead of assuming
  `checkpoints`, and never return a folder verdict for an entry whose file is
  not chosen yet.
- Agent: allow `*.cdn.hf.co` and `*.xethub.hf.co` on redirect (Hugging Face's
  own CDNs), not just four named hosts. Rebuild the agent binaries.

### Phase 2 — one vocabulary (shared + web)

- `apps/web/src/models/vocabulary.ts`: for each `ModelType`, a friendly name,
  plural, one-line explanation, the expert term, and a group
  (Models · Style add-ons · Guides · Enlargers · Parts). Everything that labels
  a type reads it: TypeBadge, filters, Discover facets, drawer, Workflows sheet,
  Create page, Settings.
- `clip` is presented as "Prompt reader (text encoder)"; the expert label
  depends on the file (CLIP vs T5) where we know it.
- Rewrite the jargon strings found by the audit (ModelPicker "checkpoints …
  graph", "No template", JobStage "cold checkpoint" / "VAE decode", Settings
  "Run VAE on GPU", workflow labels naming `diffusion_models`), and translate
  the common raw ComfyUI errors (`… not in []`) into "the model file isn't on
  this machine".

### Phase 3 — Discover that finds working models

- Open on intent: chips **Make images · Make video · Edit an image ·
  Enlarge · Style add-ons**, mapped onto task tags and `generates()`; Type and
  the expert facets (library, format) move under "More filters".
- "Works on this machine" on by default, and the default sort puts runnable
  models first.
- "Recommended" badge for a short curated list per capability.
- Parts (decoders, prompt readers) are not top-level browse results; they show
  as "Needs: …" on the model that uses them, with install handled together.

### Phase 4 — Create page for non-experts

- Model tiles lead with what the model is good at and its family; filename
  secondary. "Style add-ons" replaces "Extra styles (LoRA)" with an expert
  label. Hidden-model note rewritten in plain words with a link to Models.
- A missing part is "This model needs one more file — Get it", not
  "Needs another model" / "Wrong folder".

## Testing

Every phase lands with unit tests (vitest, Go). The whole suite runs before
each commit; the branch is deployed to dev.rippel.app only when it is green,
and the tray/agent binaries are rebuilt whenever agent code changes.

## Out of scope tonight

Authenticated (gated) Hugging Face downloads; embeddings / IP-Adapter as new
model types; splitting `clip` into separate types in the database.
